### Задание 4.
Перед запуском чат-бота нужно создать индекс с помощью скрипта из п.3

Код бота находится в файле [chat_bot.py](chat_bot/chat_bot.py) 

Варианты запуска:
1. `cd chat_bot; docker compose up -d`. Стартуют 2 контейнера, ollama и app. Сразу после старта будет загружена модель 'qwen3:8b', это может занять некоторое время.
2. Запустить непосредственно [chat_bot.py](chat_bot/chat_bot.py). Необходим `python 3.11` с установленными библиотеками `fastapi uvicorn, chromadb, langchain, langchain-core, langchain-ollama, langchain-text-splitters, sentence_transformers`. Также необходимо установить ollama и загрузить модель 'qwen3:8b'

Swagger будет доступен по URL http://localhost:8000/docs

Пример запроса: `curl -X 'POST' 'http://localhost:8000/query' -H 'accept: application/json' -H 'Content-Type: application/json' -d '{"query": "Кто такой Пол Атрейдес?"}'`

### Задание 5.
Скриншоты работы бота в папке [screenshots](screenshots)

Без фильтрации фраза с паролем суперпользователя утекала - поведение некорректное.

В текущей версии бота используется 2 вида фильтров:   
1. На уровне промпта ("КРИТИЧЕСКИЕ ПРАВИЛА БЕЗОПАСНОСТИ...")
2. Добавлена функция (filter_unsafe_chunks), отбрасывающая чанки с потенциально вредоносным содержимым.
Теперь бот ведет себя корректно, не показывая уязвимую информацию.

Возможны еще следующие дополнения:
1. Вместо простых re.search можно использовать легковесную модель-классификатор (например, небольшую BERT), которая оценивает чанки перед отправкой. Её задача — определить класс чанка (Безопасно / Конфиденциально), основываясь на смысле текста, а не на конкретных буквах.
2. Конфиденциальная информация в принципе не должна находиться в одной коллекции с публичной документацией. Стоит разделить векторные базы данных по уровням доступа (Доступно всем / Только для админов).
