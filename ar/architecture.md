# Исследование моделей и инфраструктуры для RAG-бота QuantumForge Software

# 1. Сравнение LLM-моделей

Для сравнения рассмотрим три варианта:

- локальная модель, например Qwen3-8B;
- OpenAI GPT-5 Mini;
- YandexGPT Pro.

Qwen3-8B подходит для локального развёртывания и имеет лицензию Apache 2.0. Модель поддерживается современными inference-инструментами, включая vLLM.

| Критерий | Hugging Face / Qwen3-8B | OpenAI GPT-5 Mini | YandexGPT Pro |
|---|---|---|---|
| Качество ответов | Хорошее | Очень хорошее | Очень хорошее |
| Скорость | Зависит от GPU | Высокая | Высокая |
| Стоимость | Инфраструктура | Оплата за токены | Оплата за использование |
| Конфиденциальность | Высокая | Требуется передача данных API | Требуется передача данных API |
| Развёртывание | Сложнее | Очень простое | Простое |
| Масштабирование | Требует инфраструктуры | Практически не требует | Практически не требует |
| Контроль над моделью | Полный | Ограниченный | Ограниченный |

### Qwen3-8B

Главное преимущество локальной модели — данные не покидают инфраструктуру компании. Это особенно важно для документов, связанных с клиентами и внутренними архитектурными решениями.

Недостаток — необходимость самостоятельно содержать GPU-сервер и inference-инфраструктуру.

### OpenAI

Облачная модель является наиболее простым вариантом для запуска. Не требуется самостоятельно обслуживать GPU и обновлять модель.

Например, GPT-5 Mini ориентирована на задачи с высокой нагрузкой и низкой задержкой. Текущая стоимость составляет $0,25 за 1 млн входных токенов и $2 за 1 млн выходных токенов.

Недостаток — содержимое запросов и найденных документов передаётся внешнему API. Поэтому для конфиденциальных документов потребуется отдельная политика классификации данных и разрешённых источников.

### YandexGPT

YandexGPT также предоставляет API и подходит для корпоративных сценариев.

Основной недостаток для QuantumForge — дополнительная зависимость от конкретного облачного провайдера. Кроме того, компания уже использует AWS, поэтому добавление отдельной облачной AI-платформы увеличивает сложность инфраструктуры.

### Вывод по LLM

Для production-данных повышенной конфиденциальности — локальная модель Hugging Face;

# 2. Сравнение моделей эмбеддингов

Рассматриваются:

- Sentence Transformers;
- OpenAI Embeddings.

## Сравнение

| Критерий | Sentence Transformers | OpenAI Embeddings |
|---|---|---|
| Скорость индексации | Высокая, зависит от GPU/CPU | Высокая, зависит от API |
| Качество поиска | Высокое | Высокое/очень высокое |
| Стоимость | Инфраструктура | Оплата токенов |
| Конфиденциальность | Высокая | Ниже |
| Простота | Средняя | Очень высокая |
| Контроль | Полный | Ограниченный |

## Sentence Transformers

Sentence Transformers позволяет самостоятельно запускать модели эмбеддингов. Расчёт можно выполнять на CPU или GPU, а при необходимости масштабировать обработку.

Преимущества:

- документы не передаются внешнему сервису;
- отсутствует стоимость каждого API-вызова;
- можно переиндексировать документы без дополнительных расходов;
- можно выбрать специализированную модель.

Недостаток — необходимо самостоятельно поддерживать модель и вычислительные ресурсы.

## OpenAI Embeddings

OpenAI предоставляет готовый API для получения embeddings.

Например:

- `text-embedding-3-small` — $0,02 за 1 млн токенов;
- `text-embedding-3-large` — $0,13 за 1 млн токенов.

Преимущество — очень простое внедрение и отсутствие собственной инфраструктуры для создания embeddings.

Недостатки:

- документы отправляются во внешний API;
- появляется постоянная зависимость от API;
- при больших объёмах переиндексации возникает дополнительная стоимость.



### Вывод

Для QuantumForge рекомендуется **локальная модель Sentence Transformers**.

Причина прежде всего в конфиденциальности. Кроме того, объём документации достаточно большой и постоянно растёт, поэтому постоянная локальная генерация embeddings позволит не зависеть от стоимости внешнего API.

# 3. Сравнение ChromaDB и FAISS

## FAISS

FAISS — библиотека для быстрого поиска ближайших векторов. Она хорошо подходит непосредственно для similarity search и обеспечивает высокую производительность.

Основной недостаток — FAISS является скорее библиотекой индексации и поиска, чем полноценной базой данных.

Если использовать FAISS, отдельно придётся решать вопросы:

- хранения текста документов;
- хранения metadata;
- обновления документов;
- фильтрации;
- идентификации документов;
- сохранения состояния индекса.

## ChromaDB

ChromaDB предоставляет более высокий уровень абстракции. Коллекции содержат embeddings, документы и metadata, а сама система предоставляет операции добавления, изменения, удаления и поиска.

ChromaDB поддерживает:

- vector search;
- metadata filtering;
- full-text search;
- разные embedding-модели;
- локальное развёртывание;
- клиент-серверный режим.

В single-node режиме Chroma использует HNSW для approximate nearest-neighbor поиска.

## Сравнение

| Критерий | FAISS | ChromaDB |
|---|---|---|
| Скорость поиска | Очень высокая | Высокая |
| Скорость индексации | Очень высокая | Высокая |
| Простота начала работы | Средняя | Высокая |
| Хранение metadata | Нужно реализовать отдельно | Встроено |
| Хранение документов | Нужно реализовать отдельно | Встроено |
| Фильтрация | Дополнительная реализация | Встроена |
| Обновление документов | Требует дополнительной логики | Удобнее |
| Поддержка | Простая библиотека | Готовый сервис |
| Стоимость | Низкая | Низкая |
| Пригодность для RAG | Хорошая | Очень хорошая |

### Вывод

Для QuantumForge рекомендуется **ChromaDB**.

Для корпоративного RAG-бота удобнее получить готовую модель хранения: документ + embedding + metadata + поиск.

# 4. Варианты архитектуры

Рассмотрим четыре варианта.

## Вариант 1. Полностью облачный

**OpenAI + OpenAI Embeddings + ChromaDB**

Плюсы:

- минимальное время разработки;
- высокое качество ответов;
- не требуется GPU;
- простое масштабирование.

Минусы:

- конфиденциальные документы передаются внешнему API;
- постоянные расходы на API;
- зависимость от внешнего провайдера.

**Оценка: хороший вариант для PoC.**

---

## Вариант 2. Полностью локальный

**Qwen3-8B + Sentence Transformers + ChromaDB**

Плюсы:

- документы остаются внутри инфраструктуры;
- отсутствуют расходы на LLM API;
- полный контроль над моделями;
- можно работать даже без внешнего AI-сервиса.

Минусы:

- требуется GPU;
- необходимо самостоятельно обслуживать модели;
- качество может быть ниже, чем у наиболее сильных облачных моделей.

**Оценка: лучший вариант для конфиденциальных данных.**

---

## Вариант 3. Гибридный

**Локальные embeddings + ChromaDB + выбор LLM в зависимости от типа данных**

Например:

- обычные внутренние документы → OpenAI;
- конфиденциальные документы → локальный Qwen;
- embeddings → локальная Sentence Transformers.

Плюсы:

- конфиденциальные данные можно не отправлять наружу;
- для менее чувствительных запросов можно использовать более качественную облачную модель;
- можно постепенно переносить систему в локальную инфраструктуру.

Минусы:

- архитектура немного сложнее;
- необходимо классифицировать документы по уровню конфиденциальности.

**Оценка: оптимальный вариант для QuantumForge.**

---

## Вариант 4. FAISS вместо ChromaDB

**Qwen/OpenAI + Sentence Transformers/OpenAI Embeddings + FAISS**

Плюсы:

- высокая производительность;
- небольшие накладные расходы;
- хорошая библиотека для vector search.

Минусы:

- придётся самостоятельно реализовывать хранение metadata и документов;
- сложнее обновлять индекс;
- больше собственного кода.

**Оценка: использовать только при появлении требований к высокой производительности поиска.**

# 5. Итоговый выбор

Для QuantumForge Software предлагается следующая конфигурация:

| Компонент | Рекомендация |
|---|---|
| LLM | Qwen3-8B локально |
| Embeddings | Sentence Transformers |
| Vector DB | ChromaDB |
| RAG | собственный сервис на Python |
| Inference | vLLM |
| GPU | NVIDIA L4/A10G, 24 GB |
| CPU | 16 vCPU |
| RAM | 64 GB |
| SSD | 500 GB NVMe |


Главный фактор для QuantumForge — контроль над корпоративными знаниями.

В компании присутствуют:

- исходный код;
- архитектурные решения;
- внутренние регламенты;
- клиентские спецификации;
- документация по интеграции SCADA;
- материалы для SOC 2.

Поэтому полностью передавать базу знаний внешней LLM нежелательно.

Локальные embeddings позволяют вообще не передавать исходные документы внешнему сервису. ChromaDB обеспечивает достаточно простой слой хранения и поиска. Локальная LLM позволяет строить ответы непосредственно внутри инфраструктуры компании.

При этом архитектура должна предусматривать возможность подключения облачной LLM. Например, для неконфиденциальных документов можно использовать OpenAI, что позволит получить более высокое качество ответов без изменения RAG-слоя.

# 6. Что делать с устаревшими и противоречивыми документами

Проблема QuantumForge состоит не только в поиске, но и в качестве базы знаний.

Поэтому metadata документов должна содержать хотя бы:

- источник;
- владельца документа;
- дату изменения;
- версию;
- подразделение;
- тип документа;
- уровень конфиденциальности;
- статус документа: актуальный / устаревший.

При поиске можно отдавать приоритет более новым документам и документам со статусом active.
